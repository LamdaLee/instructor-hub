# 승인된 포털 운영 반영

배포 대상: 기존 Lightsail의 instructor-hub 컨테이너. 도메인은 `https://timetable.alittlegarden.kr`이며 기존 출결앱·Caddy·DNS는 그대로 사용합니다. 클라우드 개발 환경 게시와 별개입니다.

## Lightsail 실행 순서

```bash
cd ~/instructor-hub
git status --short
# 변경 중인 코드가 있다면 먼저 별도로 보존합니다. .env는 그대로 둡니다.
git fetch origin main
git switch main
git pull --ff-only origin main
bash scripts/deploy-portal.sh
```

이미 해당 브랜치에 있다면 `git pull --ff-only origin main` 후 스크립트를 실행합니다. 스크립트는 Node.js 22 이상, Docker Compose v2, `.env`의 `DATABASE_URL`, `DATABASE_ADMIN_URL`, `SESSION_SECRET`, `APP_ORIGIN`, `CADDY_NETWORK=deploy_default` 설정을 사용합니다. 비밀값을 출력하지 않습니다. `DATABASE_ADMIN_URL`은 스크립트에만 쓰고 앱에 전달하지 않습니다.

1. npm 의존성 설치, `../hub-snapshots`에 chmod 600 gzip JSON 데이터 스냅샷을 만듭니다. `hub`와 `hub_meta`만 읽습니다. 연락처·계정 해시가 있으므로 외부 공유하지 마세요. 이 파일은 데이터 스냅샷이며 pg_dump를 대체하는 전체 DDL/역할 백업은 아닙니다.
2. 기존 앱 이미지를 `instructor-hub-rollback:before-portal`로 보존합니다.
3. 새 이미지를 먼저 빌드하고 0008 이후 새 마이그레이션을 적용합니다. 기존 데이터·원본 반 식별자·계정·수업·가져오기 기록은 유지합니다. 실패한 마이그레이션은 트랜잭션 롤백됩니다.
4. hub-app만 재시작하고 상태 점검합니다. 시작 실패 시 이전 이미지로 되돌립니다.
5. 실제 도메인에서 화면·API·관리자 로그인 보호를 검사합니다.

`.env`가 분실되었거나 `DATABASE_ADMIN_URL`이 없다면 기존 관리 URL을 서버 파일에서 복구해야 합니다. 채팅에 비밀값을 붙이지 마세요.

## 배포 버전과 42501 진단

배포 이미지는 빌드한 커밋을 `APP_REVISION`에 보존하며 `/api/health`의 `revision`으로 확인합니다. 스크립트는 실제 도메인의 버전이 현재 커밋과 다르면 배포 완료로 처리하지 않습니다. 컨테이너가 시작됐다는 출력만으로 최신 화면 반영을 판단하지 마세요.

한글이 표시되지 않는 터미널에서도 `[DEPLOY] step=...`, `[DEPLOY_ERROR]`, `[DB_ERROR] file=... code=...`, `[DEPLOY_OK] revision=...`는 영문으로 표시합니다. `42501`은 PostgreSQL 권한 오류이며 실패 단계·객체 소유권 확인이 필요합니다. 다음 읽기 전용 진단은 비밀번호·연락처·교재 내용 없이 연결 역할·권한·적용된 마이그레이션 이름만 출력합니다.

```bash
node --env-file=.env scripts/check-db-access.mjs
```

`DATABASE_ADMIN_URL`의 실제 연결 역할에 필요한 테이블·함수 소유권이 있는지와 `app_role_set`을 확인합니다. 특히 `0017`의 앱 역할 검증은 해당 역할로 전환할 권한이 필요합니다. 미적용된 `0017`을 실행할 때 마이그레이션 실행기가 DB 관리자에게 필요한 `SET` 권한을 준비합니다. PostgreSQL의 역할 관리 권한이 있는 경우에만 수행하며, 앱의 테이블 권한과 기존 상속·관리 권한은 넓히지 않습니다. 권한 준비와 마이그레이션은 같은 트랜잭션으로 실행해 실패 시 함께 롤백합니다. 원인이 확인되기 전에 앱 역할에 테이블 권한을 넓히거나 DB를 초기화하지 마세요.

## 적용되는 기능과 데이터

- 첫 화면은 전체 기수 중 선택 날짜에 수업이 있는 과정만 표시합니다. 전체/지역 시간표는 기수 필터를 지원하며 이전 기수 데이터는 유지합니다.
- 대시보드(로그인 필요): LG전자 K-뉴딜 아카데미 타이틀, 지역/기수/트랙 필터, 오늘 수업·기관·강사·담당 매니저·강의장·교재 링크, 포스트잇 공지.
- 관리자 메뉴의 **강의장·매니저**에서 지역/기수별 현재 값을 확인하고 수정합니다. 기본 강의장과 날짜별 수업 장소는 별도로 보존하며, 해당 수업에 장소가 있으면 그날은 수업 장소를 표시합니다. 두 필드만 변경하는 관리자 전용 API와 변경 전후 기록을 사용합니다.
- 전체/지역 시간표: 지역·트랙 행 × 날짜·요일 열, 시작일/종료일·주/월 조회, 중립색 셀·기관색 배지, 셀 메모. 모바일은 날짜/트랙별 카드.
- 강사 이름을 누르면 현재 화면 위 중앙 모달에서 소속·메일·전화·메모를 보여줍니다. 로그인한 계정만 볼 수 있으며 aSSIST·CLIPS 계정은 자기 기관 강사만 봅니다.
- 관리자 전용 `/admin`, 로그인 `/admin/login`. 과거 member 계정은 조회만 가능하고 일정·강사·과정·공지 수정은 거부됩니다. 교재는 관리자·LGE·LAB4DX가 모든 기관을, CLIPS·aSSIST가 자기 기관만 조회·다운로드·업로드·수정·삭제할 수 있습니다.
- 교재 업로드는 로그인한 사용자만 가능. 실제 PDF/PPTX 형식 검사, 파일당 50 MB, 현재 총 파일 메타데이터 기준 2 GiB 제한, 디스크 여유 200 MiB 검사, 15분당 출처 IP별 업로드 20회 제한. 기존 Caddy가 `X-Real-IP`를 설정하는지 확인하세요. 헤더가 없으면 공통 버킷으로 제한합니다.
- 파일명·과목·강사·등록자를 표시하고 다운로드는 attachment로 전달합니다. 파일의 교체·정보 수정·삭제는 해당 교재 기관에 접근할 수 있는 로그인 사용자만 가능하며 작업자 이름(자기 기입)과 사유를 기록합니다. 공개 여부 설정과 비공개 파일 접근은 관리자 전용. 삭제는 메타데이터와 파일을 보존하되 다운로드를 차단합니다. 교체 전 파일은 새 파일 확정 후 정리하고 변경 기록에는 전후 메타데이터를 보관합니다.
- 새 수업의 강사 배정 상태는 기본으로 비워 둡니다. 관리자가 필요할 때 `임시`/`변경예정`/`확정`을 선택하고 `선택 안 함`으로 해제할 수 있습니다. 기존에 지정한 상태는 유지하며 빈 상태는 배지를 표시하지 않습니다. 매니저·기본 강의장도 새 필드이므로 등록되지 않은 값은 `미등록`으로 표시합니다.
- 과목 이름 변경은 수업·모듈·자료·담당 과목 연결을 유지하며, 과목 삭제는 보관으로 처리합니다. 기존 과목명은 원문·변경 기록에 남습니다.

## 기관 계정과 승인 (0012)

- **가입 신청** `/signup`: 이름·소속 기관(aSSIST·CLIPS·LGE·LAB4DX)·이메일·비밀번호를 입력합니다. 비밀번호는 bcrypt 해시로만 보관하며, 같은 출처 IP 기준 15분당 5회로 제한합니다. 이미 계정이 있거나 대기 중인 이메일도 같은 응답을 돌려 가입 여부를 드러내지 않습니다.
- **가입 승인**: LAB4DX 계정(과 관리자)만 `/org`의 `가입 승인`에서 승인·반려합니다. 승인된 계정은 `운영진(member)` 권한과 신청한 소속 기관으로 만들어지며 일정·강사·과정을 직접 수정할 수 없습니다. 반려하면 저장된 비밀번호 해시를 지웁니다.
- **로그인**: `/admin/login`에서 관리자는 `/admin`으로, 기관 계정은 `/org`로 이동합니다. 관리자는 `과정·변경 기록 → 운영진 계정`에서 소속 기관을 지정·변경할 수 있고, 변경 시 해당 계정의 세션이 만료됩니다.
- **강사 명단**: aSSIST·CLIPS 계정은 자기 기관 강사만, LGE·LAB4DX 계정과 관리자는 전체 기관 강사를 봅니다.
- **강사 변경 신청**: 모든 기관 계정이 등록·삭제를 신청합니다. aSSIST·CLIPS는 자기 기관 강사만 신청하고 자기 기관 신청 내역만 봅니다. LGE·LAB4DX(와 관리자)는 승인 또는 반려(사유 필수)합니다. 승인하면 즉시 강사 명단에 반영되고, 삭제는 기록을 지우지 않고 보관 처리합니다. 처리된 신청은 다시 처리할 수 없으며 신청·처리 모두 변경 기록에 남습니다.
- 기관별 열람 제한은 포털에도 적용됩니다. aSSIST·CLIPS 계정은 강사 목록·상세·CSV에서 자기 기관 강사만 보고, 다른 기관 수업은 일정·과목·기관은 보이되 강사는 `비공개`로 표시합니다. 소속 기관이 없는 기존 내부 운영진 계정은 종전처럼 전체를 봅니다(관리자가 기관을 지정하면 제한).

## 계정 정리와 비밀번호 변경 (0014)

- **주의: 배포 시 관리자(admin)를 제외한 모든 계정이 삭제됩니다**(사용자 요청). 세션도 함께 지웁니다. 변경 기록의 이메일 원문은 남기고 계정 연결만 끊습니다. 삭제된 사람은 `/signup`에서 다시 가입을 요청해야 합니다.
- 가입 요청은 이메일·이름·소속 기관(드롭다운)·비밀번호를 입력합니다. LAB4DX가 승인하면 입력한 이메일과 비밀번호로 로그인합니다.
- 로그인한 사용자는 상단 `비밀번호 변경`(`/password`)에서 현재 비밀번호를 확인한 뒤 새 비밀번호(10자 이상)로 바꿉니다. 변경하면 다른 기기의 로그인은 만료됩니다.

## 로그인 필수 (0013)

로그인하지 않은 요청은 화면에서 `/admin/login`으로 이동하고, API·CSV·교재 다운로드·업로드는 401을 돌려줍니다. DB 함수(`hub.api_read`, `hub.api_material`)가 세션을 직접 확인하므로 앱을 우회한 호출에도 같은 제한이 적용됩니다. 열린 경로는 로그인, 가입 신청, 데이터가 없는 `/api/health`뿐입니다.

## 운영 UX 보완

- `/org`는 모바일 하단 기관 메뉴로 강사 변경 신청과 가입 승인에 접근합니다. 가입 승인 권한은 기존처럼 관리자·LAB4DX, 강사 변경 승인 권한은 관리자·LGE·LAB4DX입니다.
- 대기 건수 배지는 로그인·권한을 확인한 API 결과이며 최초 로딩, 화면 복귀, 약 1분 간격, 처리 완료 시 갱신합니다.
- LGE·LAB4DX 가입 승인에는 권한 안내와 명시적인 확인이 필요합니다. 승인 전에 소속을 정정할 수 있고 기관 정정 이력을 남깁니다.
- 세션 만료는 API 응답 또는 화면 복귀·약 1분 간격 점검으로 감지하여 로그인 화면으로 이동합니다. 네트워크 오류만으로 로그인 화면으로 보내지 않습니다.
- 관리 메뉴는 포털 메뉴 아래 별도 표시하고 비밀번호 변경·로그아웃은 이름을 누르는 계정 메뉴로 제공합니다.
- 운영 점검은 미배정·확인 필요·같은 날 중복 배정을 보여줍니다. 집계 메뉴는 추가하지 않습니다.
- 날짜별 강의장은 반별 예외 기간을 등록하고 수업별 장소 → 예외 기간 → 기본 강의장 순서로 적용합니다. 모듈·시수는 편집 화면에서 제외하되 기존 데이터는 유지합니다. 평택 외 기본 시간은 09:00~18:00이며 평택은 수업 시간을 별도로 지정합니다.
- Teams 알림 구성 방안은 [Teams 알림 안내](TEAMS.md)를 참고하세요. 자동 전송은 아직 활성화하지 않았습니다.

## 교재 기관 권한 (0018)

`0018_material_organizations.sql`은 기존 교재를 강사 소속으로 분류하고 교재 기관을 별도 필드에 보존합니다. 목록 필터뿐 아니라 파일 ID로 직접 다운로드·교체·수정·삭제할 때도 기관을 확인합니다. CLIPS·aSSIST는 타 기관으로 새 교재를 등록하거나 기존 교재를 옮길 수 없습니다. 분류되지 않은 기존 자료는 전체 권한 계정의 전체 탭에 남으며 관리자 비공개 정책도 유지합니다.

## 교재 수업 연결 (0019)

`0019_material_lessons.sql`은 교재마다 수업 연결 ID와 등록 당시 정보를 저장합니다. 새 교재의 날짜·지역·트랙은 시간표에서 선택하고 과목·강사는 서버가 선택한 수업에서 확인합니다. 여러 기수·반이 있으면 직접 수업을 선택합니다. 기존 자료는 자동 추정하지 않으며 교재 수정에서 연결할 수 있습니다. 날짜·과목·파일명의 조합에 유일성 제약을 두지 않아 같은 수업에 여러 교재, 프로젝트 기간의 같은 과목명, 같은 파일명을 모두 별개 자료로 보존합니다. 파일당 50 MB 제한과 기관별 권한은 유지합니다.

## 파일 보존과 복구

교재는 `instructor-hub_hub_materials` Docker 볼륨의 `/app/materials`에 저장됩니다. `docker compose down -v`나 볼륨 삭제를 실행하지 마세요. 정기 백업에는 이 볼륨과 DB의 hub 스키마를 함께 포함해야 합니다. 스크립트의 DB 데이터 스냅샷에는 파일 내용이 들어 있지 않습니다.

정상 시작 후 기능 문제로 이전 앱을 복원하려면 아래를 실행합니다. 추가된 DB 테이블/열과 데이터는 제거하지 않습니다.

```bash
cd ~/instructor-hub
cat > /tmp/hub-rollback.yml <<'YAML'
services:
  hub-app:
    image: instructor-hub-rollback:before-portal
YAML
docker compose --env-file .env -f deploy/docker-compose.yml -f /tmp/hub-rollback.yml -p instructor-hub up -d --no-build hub-app
rm /tmp/hub-rollback.yml
```

## 프로젝트 시간 분담 강사

시스템 관리자는 시간표의 기존 수업 카드에서 **강사 추가**를 선택해 같은 날짜·반·과목에 다른 강사와 담당 시간을 추가할 수 있습니다. 추가 강사는 강사 정보에 먼저 등록되어 있어야 합니다. 강사 추가 시 시간을 입력하지 않으며 기존 수업 시간을 그대로 적용합니다. 필요할 때만 해당 카드의 수정에서 시간을 바꿀 수 있습니다. 시간표와 대시보드는 같은 날짜에 각 배정을 시간순으로 표시합니다.

각 배정은 기존 시간표의 별도 시간대(period)로 저장하여 단독 강사 수업과 기존 데이터를 보존합니다. 한 카드의 시간 수정·삭제는 다른 배정을 변경하지 않습니다. 삭제 이력과 수업 시간 변경 이력은 기존 변경 기록에 남습니다. 교재도 해당 강사의 시간대 수업에 각각 연결할 수 있습니다. 다른 반과 같은 날짜에 배정된 강사 경고는 기존대로 날짜 기준의 확인 안내입니다.
