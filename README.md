# LG전자 K-뉴딜 아카데미

최신 운영 포털은 로그인 없는 시간표·강사 연락처 조회와 PDF/PPTX 업로드를 제공합니다. 공개 교재의 업로드·수정·삭제는 비로그인 누구나 가능합니다. 일정·강사·과정·공지 관리는 `/admin`의 관리자만 가능합니다. 과거 문서의 내부 전용 설명보다 이 정책을 우선합니다.

## 승인된 새 포털 배포

Lightsail의 기존 `~/instructor-hub`에서 새 배포 브랜치를 가져온 뒤 `bash scripts/deploy-portal.sh`를 실행합니다. 상세 절차와 복구는 [배포 안내](deploy/PORTAL.md)를 참조하세요. 기존 백업·엑셀을 다시 가져오거나 DB를 초기화할 필요가 없습니다.

# 강사 허브

내부 운영진 전용 강사·시간표 관리 서비스입니다. 로그인한 운영진은 지역·기수·트랙·기관별 시간표와 강사를 조회·수정할 수 있습니다. 관리자는 계정·반·기관·과목·변경 기록을 관리합니다.

Next.js App Router(standalone) + React + `pg` 구조이며 [출결앱](https://github.com/LamdaLee/attendance-check)의 서버·DB API 패턴을 따릅니다. 앱은 `hub_app` 역할로 `hub.api_*` 함수만 호출합니다. 테이블과 내부 함수의 직접 접근은 DB 권한으로 차단합니다. `public`·`auth`·`attendance`의 기존 데이터는 마이그레이션하거나 덮어쓰지 않습니다.

## 검토한 1·2기 자료 가져오기

첨부 자료 대조 결과와 안전 반영 도구는 [검토 자료 반영 안내](deploy/IMPORT-REVIEWED.md)를 참조하세요. 원본 파일과 연락처가 들어 있는 JSON 묶음은 저장소에 올리지 않습니다.

## 개발 환경

Node.js 22 이상, npm, PostgreSQL 16(또는 자체 호스팅 Supabase)이 필요합니다. Docker 배포는 Docker Compose v2와 기존 Caddy를 사용합니다.

```bash
npm ci
cp .env.example .env
chmod 600 .env
```

`.env`에 로컬 DB의 `DATABASE_ADMIN_URL`, `DATABASE_URL`, `SESSION_SECRET`, `APP_ORIGIN`을 설정합니다. `APP_ORIGIN`은 스킴과 포트를 포함한 정확한 출처입니다. 개발 시 `http://localhost:3000`, 운영 시 `https://hub.example.com`처럼 지정합니다. `SESSION_SECRET`에는 32자 이상의 임의 값을 사용합니다. 비밀값은 `.env`에만 보관합니다. URL의 사용자 이름·비밀번호에 특수문자가 있으면 URL 인코딩합니다.

```bash
npm run db:migrate
# APP_DB_PASSWORD를 .env에 설정한 뒤 hub_app 로그인 권한·비밀번호 설정
npm run admin -- set-app-password
# 백업이 있다면 아래 '백업 가져오기'를 먼저 실행
npm run dev
```

`DATABASE_ADMIN_URL`은 마이그레이션·가져오기·테스트·관리 CLI 전용입니다. 앱에는 `hub_app`의 `DATABASE_URL`만 전달합니다. 앱 비밀번호는 `APP_DB_PASSWORD`와 URL 양쪽에서 일치해야 합니다. `DATABASE_SSL=true`는 인증서를 검증하는 TLS 연결이며, 자체 서명 CA가 필요하면 Node의 신뢰 CA를 추가합니다. 검증을 끄지 마세요. `false`는 TLS를 사용하지 않는 로컬·사설 DB용입니다.

백업 없이 개발하려면 `.env`에 `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`를 설정한 다음 `npm run admin -- create-admin`을 실행합니다. 비밀번호는 10자 이상·UTF-8 기준 72바이트 이하입니다. 이미 존재하는 이메일은 덮어쓰지 않습니다. 생성 후 `ADMIN_PASSWORD`를 `.env`에서 지웁니다. 실제 계정을 개발용 초기 비밀번호로 바꾸지 마세요.

마이그레이션 적용 기록과 SHA-256은 `hub_meta.migrations`에 저장합니다. 이미 적용된 파일은 수정하지 말고 다음 번호의 마이그레이션을 추가하세요. 적용과 기록은 같은 트랜잭션으로 저장하며, 동시 실행은 잠금으로 직렬화합니다.

## 백업 가져오기

백업에는 연락처·계정 해시가 포함됩니다. 체크아웃 밖의 보호된 위치에 두고 권한을 제한하세요. 전체 `pg_dumpall`을 `psql`로 복원하면 기존 Supabase의 역할·시스템 스키마를 손상시킬 수 있으므로 이 가져오기 명령만 사용합니다.

```bash
npm run db:migrate
npm run import-backup -- /보호된/경로/db_cluster.backup.gz \
  --review-file /보호된/경로/hub-import.review.json
```

필요한 `COPY` 블록 6개(`classes`, `instructors`, `timetables`, `profiles`, `auth.users`, `audit_logs`)만 읽습니다. 덤프의 SQL은 실행하지 않습니다. 승인 계정만 가져오며 bcrypt 해시를 그대로 보존합니다. 기관 표기를 정규화하고, 강사는 공백 제거·NFC 정규화 후 이름으로 연결하며 동명이인은 기관으로 구분합니다. 모호하거나 찾지 못한 이름은 원문과 확인 사유를 보존합니다. 연락처는 출력하지 않습니다.

가져오기는 하나의 트랜잭션으로 수행합니다. 같은 내용의 백업은 SHA-256으로 식별하여 재실행 시 변경 없이 건너뜁니다. 새로운 백업은 원본 UUID로 갱신하므로 실행 전에 운영 DB를 백업하세요. 확인 필요 목록 파일은 강사 이름·기관 원문을 포함하므로 보호해야 하며, 기존 파일은 덮어쓰지 않습니다. 파일 옵션을 생략하면 콘솔에는 확인 필요 건수만 출력합니다.

제공된 백업으로 검증한 건수는 반 **15**, 강사 **136**, 시간표 **684**, 승인 운영진 **7**, 이전 변경 기록 **1,047**입니다. 강사가 자동 연결된 시간표는 295건이며 확인 필요는 168건입니다. 나머지 미배정과 확인 필요는 서로 다른 구분입니다. 확인 필요 목록을 검토하고 시간표 수정 화면에서 올바른 강사를 지정하면 해결됩니다. 원본의 과정명은 보존하고 화면에서는 지역·트랙·기수를 함께 표시합니다.

원본 비밀번호 평문은 보유하지 않으므로 실제 운영진의 기존 비밀번호 로그인은 운영진이 확인해야 합니다. 승인 계정 7개의 해시 원문 일치와 가상 계정의 bcrypt 로그인·실패·초기화는 검증했습니다.

## 최신 2기 통합 엑셀 반영

백업은 기존 계정·연락처·과거 이력을 복구하는 기준이고, 사용자가 제공한 최신 통합 엑셀이 **2기 과목·모듈·시수·강사 배정의 기준**입니다. 백업을 먼저 가져온 뒤 실행합니다.

```bash
# 기본 명령은 반·강사 매핑과 변경 건수만 검증합니다.
npm run import-workbook -- /보호된/경로/최신통합본.xlsx
# 검증 후 실제 반영
npm run import-workbook -- /보호된/경로/최신통합본.xlsx --apply
```

`통합시간표`, `강사목록`, `교과목_모듈` 시트의 데이터를 읽습니다. 엑셀의 수식은 실행하지 않고 저장된 결과만 사용합니다. 파일의 설명·제안은 실행 지시로 처리하지 않습니다. 반은 **지역+2기+트랙**으로 일대일 연결하며, 매핑이 모호하면 반영하지 않습니다.

최신 파일에서는 7개 반(대전1·대전2·대구1·대구2·부산1·부산2·부산3)의 이전 시간표 396건을 399건으로 교체했습니다. 강사 114명 중 기존 기록 92명에 연결하고 22명을 추가했습니다. 동일 이름·기관에 유효한 연락처까지 같은 기존 중복 11그룹은 대표 ID에 연결하며 원본 기록은 삭제하지 않습니다. 연락처가 다른 동명이인은 자동으로 선택하지 않습니다. 빈 연락처·이메일·비고는 기존 값을 지우지 않으며, 최신 강사 명단에 포함된 보관 강사는 다시 활성화합니다.

1기 시간표 288건과 기존 계정·연락처·감사 기록은 보존합니다. 반영 후 전체는 반 **15**, 강사 **158**(과거 기록 포함), 시간표 **687**건이며 2기 최신 명단은 **114명**, 교과목·모듈 매핑은 **114건**입니다. 2기 최신 명단만 보려면 공통 필터에서 기수 `2`를 선택합니다. 엑셀의 검토 표시 6건은 시간표의 확인 사유로 남겨 임의로 해결 처리하지 않습니다. 장소·메모 수정으로는 사유가 사라지지 않으며, 검토를 마친 운영진이 편집 화면에서 명시적으로 비워 저장합니다. `교육`은 수업, `공휴일`·`휴강`은 휴일, `수료식`은 공통으로 분류합니다. `프리랜서` 기관도 추가됩니다.

이전 2기 시간표는 적용 직전에 `hub.import_snapshots`에 보존하며, 스냅샷·강사 출처 매핑은 앱 역할에서 직접 조회할 수 없습니다. 가져오기 적용은 트랜잭션으로 묶고 감사 기록을 남깁니다. 같은 파일은 재실행해도 다시 덮어쓰지 않습니다. 업데이트된 파일은 해당 2기 시간표를 교체하므로 적용 전에 운영 DB 백업을 확보하세요. 엑셀 원본도 개인정보 자료이므로 저장소에 넣지 않습니다.

## 사용 방법

- **대시보드**: 오늘·이번 주 시간표, 기관별 투입 강사 수, 2주 내 미배정, 확인 필요 건수.
- **시간표**: 주간 이동, 반별 조회, 여러 반 비교, 개별 추가·수정. 같은 강사가 같은 날짜에 다른 반에도 배정되면 경고합니다.
- **엑셀 붙여 넣기**: 날짜·과목·강사·기관·장소·메모를 탭으로 구분합니다. 첫 행 헤더는 선택이며 날짜는 `YYYY-MM-DD`입니다. 미리보기 후 저장하고, 같은 반·날짜의 기존 항목은 별도 덮어쓰기 확인을 요구합니다. 시간 구분이 있는 수업은 개별 추가 화면을 사용합니다.
- **강사**: 이름·과목·지역·기관 검색과 기관별·과목별 묶어 보기. 목록에서는 연락처를 숨기고 상세에서만 표시합니다. 상세에서 월별 달력·전체 일정·반별 수업일수를 확인하며, 삭제 대신 보관합니다.
- **집계**: 기간·공통 필터를 적용한 지역×기관, 과목×기관, 강사별 수업일수. 지역·과목은 반별 날짜 수, 강사는 날짜 수로 중복을 제거하며 공통·휴일·없음은 제외합니다. 시간표 CSV에는 선택한 경우에만 연락처를 포함합니다. 스프레드시트 수식 주입을 방어합니다.
- **관리**: 관리자만 계정 추가·비활성·비밀번호 초기화, 반·기관·과목과 변경 기록을 관리합니다. 마지막 활성 관리자는 비활성화·강등할 수 없습니다. 비밀번호 초기화·계정 비활성화 시 세션을 폐기합니다.

공통 필터는 주소에 남아 공유할 수 있습니다. 세션은 8시간이며 HttpOnly·SameSite=Strict 쿠키를 사용하고 운영에서는 Secure를 적용합니다. 변경 요청은 `APP_ORIGIN`과 Origin이 일치해야 합니다. 실패한 로그인은 이메일·접속 IP 기준으로 제한합니다. 모든 날짜 기준은 한국시간입니다.

## 검증

DB 테스트는 가상 인물로 실행하며 트랜잭션을 롤백합니다. 운영 DB에서는 실행하지 마세요.

```bash
npm test
npm run db:test
npm run typecheck
npm run build
npm run start
# 별도 터미널에서, APP_ORIGIN=http://localhost:3000인 로컬 환경만 허용
npm run test:http
# Chromium 설치가 필요하면: npx playwright install chromium
npm run test:e2e
# 시스템 Chromium을 사용할 때
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

HTTP·브라우저 테스트는 로컬 DB에 가상 계정·반·강사를 만들고 종료 시 제거합니다. 브라우저 테스트는 실제 데이터의 스크린샷·동영상을 기록하지 않습니다. 테스트 결과 디렉터리에는 화면 정보가 남을 수 있으므로 커밋하지 않습니다. 프로덕션 컨테이너는 아래 standalone 시작 명령을 사용합니다.

## 집 Supabase에 적용

1. 별도 운영 DB 백업을 확보합니다. DB 소유자 권한으로 `hub`와 `hub_meta`를 생성하고 `pgcrypto`를 설치할 수 있어야 합니다. Supabase의 일반적인 `extensions` 스키마를 사용합니다. 다른 스키마에 이미 설치되어 있다면 이동시키지 말고 기존 DB 관리자에게 호환 구성을 확인하세요.
2. DB에 접근할 수 있는 관리 머신의 `.env`에 `DATABASE_ADMIN_URL`을 지정합니다. Supabase의 5432가 Supavisor 풀러라면 사용자 이름은 `postgres.<POOLER_TENANT_ID>` 형식입니다. 앱도 `hub_app.<POOLER_TENANT_ID>` 형식으로 접속해야 할 수 있습니다.
3. `npm ci`, `npm run db:migrate`, `npm run admin -- set-app-password`를 실행합니다. 앱 역할에는 테이블 직접 접근을 주지 않습니다. Supabase Data API에 `hub` 스키마를 노출하지 않습니다.
4. 위 가져오기 명령으로 백업을 넣고 건수와 보호된 확인 필요 목록을 검토합니다. 최신 통합 엑셀이 있다면 이어서 `npm run import-workbook -- 파일.xlsx --apply`를 실행합니다. 운영진은 기존 비밀번호 로그인을 확인합니다.
5. Lightsail에서 기존 Tailscale 경로로 집 DB에 접속 가능한지 확인합니다. DB 포트는 인터넷에 공개하지 않습니다.

## Lightsail 배포: 기존 출결앱과 함께

기존 Caddy와 출결앱을 유지하며 `hub-app` 서비스만 추가합니다. 새 Caddy 컨테이너를 띄우거나 호스트의 80·443 포트를 추가로 점유하지 않습니다.

1. 기존 Caddy가 연결된 Docker 네트워크 이름을 `.env`의 `CADDY_NETWORK`에 지정합니다. 외부 네트워크가 미리 존재해야 합니다. Caddy를 Docker가 아닌 호스트에서 실행하는 경우에는 이 Compose를 그대로 쓰지 말고, 호스트 로컬에만 바인딩한 별도 포트와 그에 맞는 프록시 구성을 사용하세요.
2. `.env`에 앱 역할의 사설 DB URL, 세션 비밀값, 실제 HTTPS `APP_ORIGIN`을 설정합니다. `DATABASE_ADMIN_URL`과 관리 비밀번호는 앱 컨테이너에 전달되지 않습니다.
3. 서비스 이름과 네트워크의 별칭 `hub-app`이 기존 서비스와 중복되지 않는지 확인한 뒤 실행합니다.

```bash
cd deploy
docker compose --env-file ../.env -p instructor-hub config --quiet
docker compose --env-file ../.env -p instructor-hub up -d --build
```

4. `deploy/Caddyfile.example`의 사이트 블록을 기존 Caddyfile에 추가하고 도메인을 실제 주소로 바꿉니다. Caddy도 같은 외부 네트워크에 있어야 `hub-app:3000`으로 접속할 수 있습니다. 기존 사이트 블록은 유지합니다.
5. 기존 Caddy 배포 방식으로 구성을 검증·다시 로드합니다. DNS를 Lightsail로 연결하고 HTTPS 인증서 발급을 확인합니다. `/api/health`가 HTTP 200, 운영진 로그인과 시간표 조회가 성공하는지 확인합니다. 건강 상태 API는 DB 함수 실행까지 확인하며 DB 접속 정보는 공개하지 않습니다.

앱은 외부 포트를 열지 않고 비 root 사용자로 실행합니다. Caddy가 `X-Real-IP`를 덮어쓰므로 클라이언트가 로그인 제한용 IP를 위조할 수 없습니다. 기존 출결앱과 다른 서비스 이름·Compose 프로젝트 이름을 사용합니다.

관리형 클라우드에서 HTTPS 프록시 CA가 필요한 빌드는 CA를 이미지에 복사하지 않고 BuildKit 비밀 마운트로 전달합니다.

```bash
# 저장소 루트에서
docker build --secret id=proxy_ca,src="$CODEX_PROXY_CERT" -t instructor-hub:local .
# 또는 deploy에서
docker compose --env-file ../.env -f docker-compose.yml -f docker-compose.cloud.yml build
```

TLS·패키지 체크섬 검증을 끄지 않습니다. 외부 폰트·이미지 CDN 없이 빌드하고 실행합니다. 실제 Lightsail 배포·운영 DB 변경·환경 게시와 Git 원격 push는 이 구현 작업에서 수행하지 않았습니다.
